# Vines: spans and curtains — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace ticket 18's straight vine strands with braided liana **spans** across corridors (cap to cap, fading when Pip is near) and **curtains** down south faces, all swaying slowly.

**Architecture:**

- **Planning (`src/core/decor.ts`):** two pure, seeded planners decide where spans and curtains go.
- **Asset (`build_vines.py` → `vines.glb`):** a new bpy builder writes 4 span variants and 4 curtain variants, split into single-material parts.
- **View (`src/render/vines.ts`):** instances the variants from per-view clones of the kit. One `onBeforeCompile` patch adds the sway and a dithered per-instance fade.
- **Cutover:** the ticket 18 `vine` kind is retired in a separate final task.

**Tech Stack:** TypeScript 6 strict, three.js 0.187 (InstancedMesh, `onBeforeCompile`), Blender 5.2 bpy, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-15-vines-design.md` (approved 2026-11-15; its "Revisions after plan validation" section records the human's later choices). Read it before any task. Repo rules are in `CLAUDE.md`.

**Out of scope** (from the spec): vines in rooms or on non-south faces; vines that react to Pip; unique geometry per span; audio; any gameplay effect. The generator stream and v2's decor draws stay untouched.

## Global Constraints

- **Layering:** `src/core` imports no three.js or DOM.
- **Colours:** no colour literals outside `src/render/palette.json`. `tests/unit/no-colour-literals.test.ts` enforces this, and in Python it also matches float triples like `(0.3, 0.5, 0.2)`, so build vectors with `Vector((…))`.
- **Determinism:**
  - Never use `Math.random`.
  - Stream offsets are exported constants in `src/core/decor.ts`: `DECOR_STREAM = 500` (existing literal), `CURTAIN_STREAM = 1500`, `SPAN_STREAM = 2500`. `src/core/hazards.ts` uses 1000.
  - Each planner calls `tileRng(seed, col + OFFSET, row + OFFSET)`.
- **Baselines:** `generator-baseline` and `decor-baseline` stay green.
- **Shaders and lights:** no shader compiles mid-play, and no light is added, removed or toggled. `rig-guard` and the post-boot program count stay at baseline.
- **Feel values:**
  - Live in `look.decor`. Every value is read every frame (panel edits are live) except `spanChance` and `curtainChance`, which are read at level build.
  - Sway and fade run on sim time (`timeMs` from `heroFrame`).
  - Under reduced motion the sway amplitude is 0, but the fade still runs.
- **Geometry rules:** spans and curtains cast no shadows. Nothing from a span hangs below 1.6 m above the floor inside the corridor gap.
- **Blender:** build only via `./blender/blender.sh --background --factory-startup --python-exit-code 1 --python blender/scripts/<builder>.py`. Never `pnpm assets:build`, which churns `pip.glb`. Commit GLBs via LFS.
- **e2e:** on its own port: `DEV_PORT=5199 pnpm test:e2e --workers=2`.
- **Every task** ends with `pnpm check` → PASS before its commit. Every commit message ends with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Pip already under a span** when a level builds, or after any jump of more than one tile (respawn). The span is faded on that frame and never eases while he's hidden. Covered in Task 4: the fade snaps on the first update and on any hero jump greater than `TILE_SIZE`.
2. **Sim time that holds or goes back** (hit-stop, `pause()`, a rebuild). The step stays ≥ 0, `lastMs` follows `timeMs` every update, and a later forward step still moves the fade. Covered in Task 4.
3. **A level with fewer spans after one with more:** no stale instances, and `fades()` matches the new plan. Covered in Task 4.
4. **Reduced motion switched on mid-play:** the sway goes to 0 on the next frame. Covered in Task 4.
5. **A dual-key or hazard-dense level:** no span or curtain over key 2, any trap, a patrol, a coin or the chest. Covered in Task 1 with synthetic levels and chance 1.

- [ ] **Step 1: Write the failing tests.** Apply the patched `onBeforeCompile` to a fake shader built from `ShaderLib.standard`.
  - **`declares the fade attribute and varying at #include <common>, and sets vFade after begin_vertex`:**
    - `attribute float instanceFade` and `varying float vFade` appear right after the vertex shader's `#include <common>`;
    - `vFade = instanceFade` appears after `#include <begin_vertex>`.
  - **`discards against a 4×4 ordered-dither threshold right after clipping_planes_fragment`:** the fragment shader contains `discard`, `gl_FragCoord` and `varying float vFade`. The index of `discard` is greater than the index of `#include <clipping_planes_fragment>` and less than the index of `#include <color_fragment>`.
  - **`sways by depth below the origin`:** the vertex shader contains `swayAmp`, `swayDepth` and `instanceMatrix[3]`.
  - **`shares the uniforms object`:** `shader.uniforms.swayAmp === uniforms.swayAmp`.
  - **`uses one fixed program cache key`:** `customProgramCacheKey() === 'vine'`.
- [ ] **Step 2: Run the tests.** `pnpm vitest run tests/unit/vine-material.test.ts` → FAIL.
- [ ] **Step 3: Implement it** in the manner of `addRim` (`src/render/hero.ts:198`).
  - **Sway weight:** `w = clamp(-position.y / swayDepth, 0.0, 1.0)`, in the node frame, so anchors and the cap stay still and bark and leaves move together.
  - **Phase:** from `instanceMatrix[3].xz` and `position.x`.
  - **Offset:** `transformed.xz += w * swayAmp * sin(6.2831853 * swayHz * swayTime + phase) * vec2(1.0, 0.6)`.
  - **Discard rule:** discard when `vFade < bayer4x4(gl_FragCoord.xy)`, with thresholds strictly inside (0, 1). So 1 never discards and 0 always does. A constant array indexed dynamically is fine on WebGL2.
